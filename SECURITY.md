# Security and privacy

- Full-workshop attendees keep their existing private Lab 1 copy, same Mona exercise and same Project. Optional standalone learners use this Lab 2 template once to make their own **Private** copy and one private Project. All participation is browser-only; public source repositories are inert and must not receive learner answers or account screenshots.
- Mona's reusable runtime skips all three public workshop sources and requires a private, non-template copy on main. Human learner identity and repository ownership or authorized owner-admin access are checked before exercise writes. It creates **only one Mona exercise issue**, never work issues or Projects. Learners manually create the two exact-title work issues after the exercise opens.
- The first Project address-bar link binds the native work issues after checking exact titles, immutable issue IDs, learner authorship, creation time and open state. Lab 2 later checks native dependencies, PR linkage, the unchanged checked head, merge and issue state. Missing evidence and API errors fail closed.
- All Project UI work is **SELF-CONFIRMED**: existence, private visibility, access, repository linkage, membership, Assignees grouping, Effort, Sprint, Status, dates, views and automation. Mona uses **no Projects API** and does not grade screenshots. A saved URL or successful offline check does not prove a Project action occurred.
- The verification workflow is read-only: **contents: read**, pinned official Actions, Node 24, no persisted checkout credentials, dependency installation or secrets. Its pull-request trigger cannot write progress. It checks publication content offline, not live permissions or Project state.
- The separate Mona caller grants only **contents: read**, **issues: write** and **pull-requests: read** to the built-in **GITHUB_TOKEN**. Both the Lab 1 reusable workflow reference and its runtime-ref input must be the same full **40-character commit SHA**, never a branch, tag or unresolved placeholder. The runtime treats the caller's guide and metadata as data, not executable scripts; it ignores PR conversations and unsupported events. No supplied secrets or privileged pull-request trigger is needed.
- Use only normal browser sign-in. No participant PAT, App, instructor account or additional credential is required. Never paste secrets into comments, repository files or reports; preserve inherited access and review protections.
- Use synthetic training data only, not real BSP data or original proposal documents. Browser downloads and account screenshots stay private; do not publish exports with the guide.
- Inspecting your own PR's Files changed is **not independent review or self-approval**. Neither offline checks nor Mona completion establish independent assessment, approval or compliance.
- Respect account entitlements, organization protections and inherited access. Do not weaken them to complete a workshop activity.

Report a vulnerability privately through the repository owner's contact on the [organization profile](https://github.com/alvine-aurelio-org). Do not include an actual credential in a public issue. If a credential was exposed, revoke it through its issuer's supported process.
